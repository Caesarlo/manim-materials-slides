## web/deck.js

```text
Runtime for live decks: every slide is a module that draws into its own 16:9 frame (HTML, SVG, and
manim-web scenes via window.ManimWeb), and Reveal.js only supplies navigation, steps and speaker notes.

A slide module registers itself:

  Deck.slide('outline', {
    steps: 2,                        // click-steps on the slide (default 1)
    notes: 'speaker notes',
    interactive: true,               // the slide takes drags/scrolls (no swipe-to-navigate on touch)
    smoothBack: true,                // it plays steps in reverse on one click back (see Deck.start's smoothBack)
    mount(frame, ctx) {              // build into `frame`; ctx = {theme, palette, data, M, css, esc}
      return {
        enter(step, animate) {},     // show steps 1..step. animate: true going forward; 'back' for one click
                                     // back (play the step in reverse, quickly, if it makes sense); false: jump
        leave() {},                  // off screen: stop anything running
        freeze() {},                 // optional: redraw canvases now, so the deck can picture them
        destroy() {},                // unmounted to stay under the browser's WebGL context limit
      };                             // (enter may return a Promise that settles when the step is shown)
    },
  });

and the deck page lists the modules in order, then calls Deck.start({title}). Press T to switch theme,
L for a laser pointer (shared with the speaker view); left click steps forward, right click back. A 3D view turned in one
window turns in the other too: see Deck.shareView.

Helpers for slides: Deck.show(frame, step, animate) reveals the elements marked data-from="k" (shown from
step k on) or data-show="1 3" (shown on exactly those steps); Deck.points([...]) writes a numbered column
(.deck-col in deck.css); Deck.manim (web/manim.js) runs a manim-web scene a click at a time.

The section footer: Deck.sections([[num, name], ...]) names the talk's sections (outline.js does), and a
Deck.section(num) between the page's script tags puts the slides listed after it in that section. Every
slide in a section shows the numbered sections along the bottom, its own lit; click one to go there.
Deck.topics({num: [[title, [slide names], blurb], ...]}) splits a section into topics: the current
section then shows a dot per topic (solid when done, accent for the one you are in, hollow ahead), and
Deck.topicsOf(num) gives them to a checklist slide. Deck.expand(num) gives a dense section the whole
footer while you are in it: the sections before it shrink to their numbers, and its topics spread along
the bar as numbered segments (num.1, num.2, ... in topic order) that fill like a progress bar.
```

## web/manim.js

```text
A manim-web scene that builds up a click at a time: the on-click transitions of a manim talk, live in the
browser. You describe the scene's objects once and what each click does to them; the stage plays a click's
animations when you step forward, and when you jump (back a step, or onto the slide from a later one) it
rebuilds the objects and applies the steps up to there instantly, so every step looks the same however
you reached it.

  const stage = Deck.manim(host, {
    build: ({ M, P }) => ({                                 // fresh objects; called again on every rebuild
      dot: new M.Dot({ color: P.accent }),
      square: new M.Square({ sideLength: 2, color: P.fg }),
    }),
    steps: [                                                // steps[k - 1] takes you from step k - 1 to k
      ({ dot }, { M }) => [new M.FadeIn(dot)],             //   return the animations to play together...
      async ({ dot, square }, { M, play, wait }) => {      //   ...or call play() as often as you like
        await play(new M.Transform(dot, square));
        await wait(0.3);
        await play(new M.Indicate(square));
      },
    ],
    scene: { frameWidth: 16, frameHeight: 9 },             // optional: M.Scene options (these are the defaults)
  });

and in the slide's mount():

  return { enter: stage.go, freeze: stage.freeze, destroy: stage.dispose };

Step 1 is what plays as the slide arrives; a slide whose first frame should be still can make steps[0]
add things without animating (`({ a }, { add }) => add(a)`). The scene is transparent, so the slide's
background and HTML text show around it; put HTML text over it in the slide, or use M.Text / M.MathTex
inside it. World units: x right, y up, origin at the centre, frameWidth x frameHeight across the host.
Colours come from ctx.palette (P), so both themes work; never hard-code white or black.
```

## web/plots.js

```text
Charts for the live decks, laid out one way everywhere (the rules are in web/deck.css, under "Plots"):
the slide heading; a small legend centred under it with room to breathe; a compact chart with wide side
margins; each group's label hung under its own bars, so it is centred on them; a small light-grey footnote
at the bottom. With nothing at the bottom (no caption), the chart drops lower, clear of the title.

  const plot = Deck.groupedBars(frame, {
    series: [{ key: 'a', label: 'Method A' }, { key: 'b', label: 'Method B' }],   // colours: --plot-1, -2, ...
    groups: [{ key: 'small', label: ['Small', 'inputs'], step: 2, highlight: false,
               values: { a: [59, 144], b: [80, 144] } }, ...],   // [count, of], drawn as a percentage
    strong: 'b',                 // optional: the series whose values are set in bold
    footnote: ['Source: ...'],
    captioned: false,            // true when the slide puts a caption under it (the chart then sits higher)
  });
  plot.show(step, animate);      // groups whose step <= step grow in; call it from the slide's enter()

Values are [count, of] pairs, drawn as percentages with ticks every 25%. For plain numbers instead, give
`max` (the top of the axis) and optionally `ticks` (default 4 intervals) and `format` (value -> label):

  Deck.groupedBars(frame, { max: 40, format: (v) => `${v} ms`, series, groups: [{ ..., values: { a: 12 } }] })

A series may carry a `step` instead, and then the chart builds up a series at a time with every group on
screen from the start: one colour joins each group on each click, rather than one group arriving whole.
Give the steps to the groups or to the series, not to both. A single series is a plain bar chart.
```

## web/addons/molstar.js

```text
A Mol*-like look for manim-web 3D scenes (Mol* is the viewer on the PDB's pages): a dark outline wherever
depth jumps (around each atom and where it passes in front of another), ambient occlusion in the creases
where bonds meet atoms and atoms crowd each other, matte surfaces under a soft key light beside the viewer,
and a little depth fog. Our own shaders, tuned against Mol* (MIT): D. Sehnal et al., Nucleic Acids Res. 49,
W431 (2021). Atom colours: Jmol's.

  const look = Deck.molstar(scene, { scale: s, fog: [near, far] })  // right after making the scene; s is the
  look.fog(near, far)              // slide's scene units per Å. Colour atoms with palette.cpk. Move the fog
  look.scale(s)                    // as the camera does, and the scale if the slide zooms or learns it later.

THE DECK'S LOOK is Deck.molstar.look, below, in Å and CSS pixels so every slide looks alike whatever its
scale. Change it there, or for one talk from its page before the slides mount:
  <script>Deck.molstar.configure({ occlusion: { strength: 1.2 } })</script>
and for one slide, pass the same keys to Deck.molstar(scene, {...}).

It takes over the scene's draw: the scene renders offscreen with its depth buffer, an occlusion pass reads
the depth (SSAO: samples a hemisphere over each surface point, rebuilt from depth), and a final pass blurs the
occlusion and adds outline and fog. Fog distances are in scene units, from the camera.
```

## web/addons/turntable.js

```text
A 3D stage for molecules and other models: a transparent manim-web ThreeDScene with the Mol*-like look
(web/addons/molstar.js), a camera you can turn by dragging and zoom with the wheel, and a gentle idle rock
so the model reads as 3D while you talk. Turning moves the camera, not the model, so anything in the scene
(manim mobjects such as M.Molecule3D, or plain three.js meshes such as Deck.cartoon) turns together.

  const view = Deck.turntable(host, {

    scale: 0.16,          // scene units per Å, for the look's Å-based outline and occlusion
    rock: 0.4,            // radians either way while idle (0: still)
    tilt: 0.25,           // radians the camera starts above the equator
  });
  view.add(mobjectOrMesh);         // M.Molecule3D and other mobjects, or any THREE.Object3D (scene units)
  view.model.add(mesh);            // or three.js objects in Å: view.model is a group scaled by `scale`
```
